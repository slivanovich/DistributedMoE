# Введение в предметную область: отказоустойчивый инференс large-scale MoE моделей

## Эволюция архитектур больших языковых моделей

Современные большие языковые модели достигли впечатляющих результатов, но их масштабирование сталкивается с фундаментальными ограничениями. Традиционные плотные архитектуры требуют активации всех параметров для каждого токена, что приводит к квадратичному росту вычислительных затрат при увеличении размера модели. Mixture-of-Experts (MoE) архитектуры предлагают элегантное решение этой проблемы: вместо одного большого плотного слоя используется множество специализированных экспертных подсетей, из которых для каждого токена активируется лишь небольшое подмножество (обычно top-k экспертов).

Эта разреженность активации позволяет значительно увеличить общее количество параметров модели при сохранении константных вычислительных затрат на токен. Однако она же создает новый класс вызовов: если в плотных моделях узким местом является вычислительная мощность, то в MoE моделях критическим фактором становится эффективность коммуникации между узлами.

## Проблемы распределенного инференса MoE моделей

При инференсе больших MoE моделей возникает необходимость в распределении экспертов по множеству GPU, поскольку память одного устройства не может вместить все веса модели. Это приводит к архитектуре Expert Parallelism, где:

1. **Статическое размещение экспертов**: глобальное множество экспертов разбивается между узлами, каждый узел хранит подмножество экспертных весов
2. **Динамическая маршрутизация**: для каждого токена гейт-функция определяет необходимых экспертов, что требует передачи активаций к соответствующим узлам
3. **Коллективные коммуникации**: традиционно используются операции all-to-all для диспетчеризации активаций и сбора результатов

### Ограничения коллективного подхода

Современные системы инференса MoE полагаются на коллективные примитивы (в первую очередь all-to-all), которые обеспечивают высокую пропускную способность, но имеют критические недостатки:

- **Глобальная синхронизация**: все участники должны одновременно участвовать в коллективной операции
- **Хрупкость к отказам**: сбой любого узла приводит к остановке всей операции
- **Чувствительность к страглерам**: медленный узел замедляет всю группу
- **Статичность**: сложность адаптации к изменяющимся паттернам нагрузки

Эти ограничения становятся особенно критичными при масштабировании на сотни и тысячи GPU, где вероятность отказов и неравномерности нагрузки значительно возрастает.

## Мотивация peer-to-peer подхода

Альтернативой коллективным коммуникациям является использование peer-to-peer (P2P) передач данных между узлами. Этот подход предлагает следующие преимущества:

### Отказоустойчивость
- **Локализация отказов**: сбой узла влияет только на непосредственно связанные с ним операции
- **Возможность переназначения**: экспертные вычисления могут быть перенаправлены на альтернативные узлы
- **Graceful degradation**: система может продолжать работу с пониженной производительностью

### Гибкость маршрутизации
- **Адаптивная балансировка нагрузки**: возможность динамического перераспределения работы
- **Топологическая осведомленность**: оптимизация передач с учетом физической топологии сети
- **Асинхронность**: отсутствие глобальных точек синхронизации

### Управление потоками
- **Backpressure**: механизмы предотвращения переполнения буферов
- **Per-peer flow control**: независимое управление потоками для каждой пары узлов
- **Приоритизация**: возможность обработки критичных запросов в первую очередь

## Технические вызовы P2P подхода

Переход к P2P архитектуре требует решения ряда сложных технических задач:

1. **Поддержание пропускной способности**: обеспечение того, что множественные P2P передачи могут достичь агрегированной пропускной способности, сравнимой с коллективными операциями

2. **Координация без глобального состояния**: разработка протоколов, позволяющих узлам принимать локальные решения, приводящие к глобально оптимальному поведению

3. **Мониторинг и восстановление**: создание систем непрерывного мониторинга состояния узлов и быстрого восстановления после отказов

4. **Оптимизация использования ресурсов**: эффективное перекрытие коммуникаций и вычислений для максимального использования пропускной способности сети и вычислительных ресурсов

Данный проект представляет практическую реализацию P2P-based архитектуры для отказоустойчивого инференса больших MoE моделей, демонстрируя возможность достижения производительности, сравнимой с коллективными подходами, при значительном улучшении отказоустойчивости системы.
